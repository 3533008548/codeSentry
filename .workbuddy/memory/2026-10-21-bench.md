# 2026-10-21（续）

## 索引层性能基准实测 · 修正 v0.2 一处设计

用户问"自进化对电脑配置有什么要求" → 顺手做了本机基准测试，**结果推翻了 v0.2 的一处设计**。

### 本机配置

i7-12700H（14核20线程）/ 15.8GB 内存（实测时仅 3.1GB 空闲）/ RTX 3050 4GB / Python 3.13.14

### 实测数据（19.6 万行模拟项目，30,240 符号 / 40,320 引用边）

| 阶段 | 耗时 |
|---|---|
| AST 解析 + 符号/边表构建 | 8.89s（22,054 行/秒） |
| 引用图构建 | 0.022s |
| PageRank 全量 | 0.032s |
| 增量重解析 1 文件 | 1.7ms（vs 全量提升 5,146x） |
| **峰值内存** | **14.1 MB** |

PageRank 规模敏感度（纯 Python）：500 节点 1.1ms / 2,000 节点 4.6ms / 8,000 节点 27ms / **30,000 节点 169ms**。

### 三处设计修订

1. **删除"局部近似"折中路径**。v0.2 初稿认为"PageRank 是全局计算，改一文件影响全图"所以增量场景用反向引用计数+层级深度近似。**实测证明理由不成立**——169ms 相比 AST 的 8.9s 可忽略。而局部近似质量代价明显：**Top20 重合度 16/20，Top50 重合度仅 11/50**。改为每次全量重算。
2. **不引入 numpy / scipy / networkx**。纯 Python PageRank 60 行即可，够用；且 **Windows 上安装 scipy 需编译 C 扩展，实测直接超时**（pip install 被 SIGTERM）。零重依赖是环境搭建目标。
3. **新增 §6.3.1 资源需求实测**：自进化成本在 API 调用次数不在本地算力；本地峰值内存 14MB、GPU 零参与。唯一注意项是内存余量（M4 引入 ts-morph 需额外 200-500MB）。

### 方法论收获

v0.1 定过"trade-off 必须写进 README，不假装解决了"。本次实测同时验证其反面——**当 trade-off 实际不存在时，不要为了显得严谨而制造它**。声称"我们做了折中"而不给数据是伪严谨。
