# 2026-10-21（续二）

## 真实项目索引实测 · research_agent

目标：`D:\develop\academic\research_agent`（77 提交，Python 41,897 行生产代码 + 3,965 行 TS）

### 目标项目关键发现

- **`runtime/` 是数据目录不是源码**：465 个 .py / 175,589 行，占全仓 Python 行数 **80%**，内容是论文库、实验产物、临时文件。不排除则排序彻底失真 → **排除规则是索引层一等功能，不是配置项**
- 真实源码构成：顶层 46 文件 19,745 行 + api/evals/scripts/tests/tools 22,042 行 + frontend 3,965 行

### 第一版原型 PageRank 排序失败（致命）

三个缺陷，全部只在真实代码上暴露，模拟数据测不出：

1. **符号未限定**（致命）：裸符号名做主键 → 1,206 个定义只有 990 唯一名（**重名率 18%**），`get` 在 8 个文件各定义一次 → 节点合并 → PageRank 给"最常见的词"打分。实测 Top1 是 6,101 行的 tests/test_core.py，核心符号全是 get/append/list
2. **入口点过宽**：仅用 `__main__` 守卫 → 命中 **54 个**（22 scripts + 25 tests），召回 100% 但精确率仅 11%
3. **未解析调用未分类**：86.6% 混在一起无法评估解析器质量

### 修订后（v2 原型 prototype_index_v2.py）

- 符号主键改限定名 `file::symbol` → 唯一名 990 → 1,101
- 文件级 Top12 全部命中真实架构组件：runtime_paths(0.0308) / tool_runtime(0.0212) / session_store(0.0110) / config(0.0080) / resilience / paper_store / mcp_client
- 符号级 Top：append(api/run_manager.py:31) / ensure_initialized(runtime_paths.py:119) / get_runtime_paths / from_root / load(config.py:138) / execute(tool_runtime.py:83) / PaperStore / raise_if_cancelled(cancellation.py:16) —— 精确对应项目真实架构
- 入口点收敛到 **3 个应用入口**：research_agent.py / api\app.py / api\routes.py
- 调用四分类：builtin 49.9% / local+cross_file 16.5% / external 11.7% / test_helper 8.4% / unresolved 12.8%
- **纯 AST 符号解析天花板约 60–70%**：unresolved 里 1,084 条是标准库**类方法**（datetime.now / sqlite3.commit —— ast 看不到类的方法），256 条是同名多定义歧义
- 性能：L1+L2 端到端 **< 1s**，峰值内存 14MB，比 v0.2 目标（L1<30s/L2<3min）有 30–180 倍余量

### 踩到的第二个坑（比第一个更隐蔽）

符号级排序若按符号名统计入度再分配给同名定义，8 个 `get` 会**每个都拿到全部入度**（85 文件）→ 排序仍被 get 霸榜。**正确做法：符号级只用唯一定位的符号，歧义符号不参与符号级排序但仍参与文件级排序**（文件级只需知道"有调用发生"）。
