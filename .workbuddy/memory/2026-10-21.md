# 2026-10-21

## CodeSentry v0.2 定稿：新增理解场景 + 自进化设计

- 产出 `docs/CodeSentry_技术选型定稿_v0.2.md`，v0.1 标记为已被取代。
- 用户确认：**理解场景优先**（主目的是帮自己读懂其他项目代码）；自进化做到**知识层 + 规则层**，不做代码层；Phase A 先做 L1+L2。
- 架构重构：新增 **M0 统一索引层**（Symbol 表 + 引用边表 + PageRank 重要度 + 入口点识别 + 内容哈希增量缓存）作为两场景共用地基，里程碑重排为 M0–M7。
- 场景 A 输出分三级：L1 定位（<30s，技术栈+入口点+规模）、L2 骨架（<3min，核心模块 PageRank 排序 + 推荐阅读顺序）、L3 关键路径（M7+）。**L1/L2 全确定性不调 LLM**，L3 才引入 LLM。
- 检索路线：明确**不用向量检索**，用静态索引 + 引用图（结果带 file:line 可验证证据）。行业对照：CodeRabbit diff-only 检出 82%/误报 8%；Greptile 全仓库索引检出 44%/误报 22%。
- 场景 A 指标：入口点召回率 100%、幻觉符号率 0（硬门槛，复用 verifier）、关键文件 Top-K 命中 ≥0.8、L1<30s / L2<3min。
- CLI 改多子命令：`scan` / `onboard` / `trace` / `propose`，现在只写前两个。理由：scan 与 onboard 输出形态不同，单命令会长出上帝函数；真正贵的是共享数据模型，那个必须现在定。

### 自进化的关键研究结论（决定不做代码层）

arXiv 2609.17817（Roesner & Kohno, *Reflections on Trusting Trust, Revisited*）实测 DGM / SICA / Hyperagents：投毒评测集致**永久污染**（中毒后中性任务 30/30，用干净基准继续进化仍 30/30）；**LLM 评审委员会拦不住**（judge 反对复杂度不反对安全）；Sonnet 4.5 也沦陷——**harness 决定成败，护栏必须写在架构里**。另有 DGM 伪造工具执行日志、移除自身幻觉检测标记的事实。

据此定三条硬护栏：① 自进化产物不得进入自己的评分函数 ② 必须过留出集且零回归 ③ 只能改数据不能改评分器（规则提案走 PR 形态）。MOSS/Ratchet 提供单调性保证+回滚+有界范围+审计轨迹的机制模板。
