## 一、阶段总览与交付节点

P4新增项目带学交付：中央多轮问答、项目级持续授权、有界原文检索、证据引用、独立话题/约束/反馈与可调侧栏；先交付可试用功能，真实项目带学质量与重构收益另评估。P5跨项目知识与P6规则晋升不因本地聊天记录的存在而记为完成。见[2026-11-02实施与预览对照](execution/P4_项目对话与带学界面_20261102.md)。

分为 **P0 准备阶段 + P1–P7 七个交付阶段**。P 是执行顺序编号，M 是技术模块编号；两者不一一对应。

| 阶段 | 目标与主要任务 | 预期成果 | 主要指标/完成条件 | 对应 M |
|---|---|---|---|---|
| P0 基线与验收准备 | 核对现状，冻结范围、标签口径和任务清单 | 基线记录、指标定义、样本分割与待办 | 能复算基线，未知显式记录，调优前固定评测规则 | 全阶段准备 |
| P1 工作空间导航 | 复用静态基础，独立workspace/API/浏览器工作台及统一文件访问权限 | 工作空间导航版，CLI保留自动化 | 导航既定P@10/入口/位置/性能指标不变；另过隔离、文件权限/迁移和真实浏览器验收 | M0/M1补强、M1.1 |
| P2 隔离执行与评测基础 | 数据裁决、分组分割、独立评分；首个 runner 验收 | 版本化数据与评分器、受限执行后端 | 评分可复算、金标隔离、执行反例通过；不提前验收检测效果 | M2基础、公共runner |
| P3 确定性审查与门禁 | 首批规则、可信Finding、指纹/基线、diff、CI | 可独立于模型工作的门禁版 | 适用缺陷集precision≥0.85、recall≥0.70；不完整不pass；可信边界反例通过 | M3、M2效果验收 |
| P4 语义辅助审查 | 候选裁决、回验、数据/预算控制、故障降级 | 带证据的语义警告与理解试验报告 | 原始模型结论不直接阻断；阶段召回、正确率、成本与时延可核查 | M4 |
| P5 可追溯知识 | Insight证据、作用域、漂移与退役 | 可核对、可失效的项目知识库 | 漂移检出率≥0.9；失效知识不当事实，记忆不修改门禁 | M5 |
| P6 规则提案与准入 | 提案、dev开发、冻结封存评估、人工晋升/回滚 | 可审计的规则演进链路 | 未准入不写active；固定反例无回归；满足预登记统计要求 | M6 |
| P7 补丁与深挖 | L3任务、隔离副本生成/验证、按授权应用 | 带验证证据的深挖与补丁能力 | 范围/快照/平台匹配；不完整不记已验证；通过不自动合入 | M7 |

表中阈值均按下文的适用范围、标签与证据条件判断，不能只看汇总百分比。P1是修补并重测现有功能，不重新开发一套M0/M1。

**可独立交付的节点**：P1工作空间导航版、P3确定性门禁版、P4语义辅助版。P1.7–P1.9先形成可用开发预览，界面交互通过不代表导航质量已达标；P1整体完成仍满足既定硬门槛。P5–P7是后续增强，首个可用版本不等待全部完成。

## 二、依赖、并行与执行规则

| 工作 | 必须先具备 | 可并行或不必等待的部分 |
|---|---|---|
| P1静态补强 | P0范围、导航标签和验收定义已固定 | 不等待Docker，不运行目标业务/插件 |
| P1.7–P1.9工作空间/API/UI | 可信结构接口稳定、工作空间数据合同固定 | 可在旧代理P@10未过80%时开发；界面验收与分析质量分开，不降低原门槛 |
| P1.10/P1.11文件权限与迁移 | 已确认的三档权限、Git规则范围、拒绝优先、撤销与迁移合同 | 本地AccessPolicy、权限界面与迁移已实现并通过本机功能验收；原文准备与mock不代替P4真实出口，外来衍生内容一律拒绝 |
| P2A数据与评分 | P0任务与分割规范 | 可与P1并行；后续扩充缺陷数据，不追认开发项目为封存集 |
| P2B runner | 任务、快照及环境接口稳定，明确首个支持平台 | 可与静态开发并行；在首次安装目标依赖、收集测试或运行目标代码之前验收 |
| P3确定性审查 | P1可信结构/完整性接口、P2A适用标签与评分器 | 纯静态规则可先开发；动态复现必须等待P2B。导航排序分数未达标不阻止独立开发，但P1不能据此标为完成 |
| P4语义能力 | 可信候选/门禁接口、P2A评测、P1.10/P1.11访问策略、具体模型/用途授权与预算配置 | 不需要P5/P6；先做小范围试验，真实模型/embedding出口须复用并验收统一策略 |
| P5知识 | P1证据/环境接口、P4所需语义能力 | 不需要规则自动晋升或补丁能力 |
| P6规则提案 | P2A/P2B、可信门禁与相应语义能力 | 若使用Insight才另依赖P5；不强制所有知识能力先完成 |
| P7A L3深挖 | P1与相应语义能力 | 不需要P5/P6；涉及运行证据时另需P2B |
| P7B补丁 | P1可信快照、P2B、P3门禁及相应生成能力 | 不需要先实现知识和规则演进 |

P1.7–P1.9首版已有本机验收，P1.10/P1.11本地文件权限与迁移也已通过本机功能验收，同时继续保留P1.6标签与导航质量缺口；之后完善P2/P3/P4。后续按实际价值选择P5、P6或P7分支。数据规范与评测隔离从P0开始，不能等到最后再补。

2026-10-28起，P1按开发预览基线交接并冻结新增功能，P1-Q1人工标签/入口、P1-Q2理解试验、P1-Q3时延稳定性留作具名待办；正式状态仍未通过。优先推进不依赖这些质量结论的P2A离线设施；执行类任务仍须先通过P2B，不因进入下一阶段自动获得能力。

每阶段分别记录：功能是否完成、任务是否适用、证据是否充分、正式验收是否通过。前置接口稳定后可以继续独立开发；指标失败、证据不足或不适用都不能被写成“本阶段验收通过”。

阶段状态使用未开始、进行中、待外部条件、待验收、通过、未通过；单项可标不适用并给依据。未解决的前置缺口要指向具体任务，不以降低阈值、缩小分母或隐藏失败结案。

## 三、P0 基线与验收准备

**目标**：明确从哪里开始、做哪些范围、用什么证据判断完成。

| 任务 | 具体工作 | 产出 |
|---|---|---|
| P0.1 核对现状 | 记录源码版本、工作区差异、现有命令和占位功能；复测可安全运行的工具自身测试 | 当前能力/缺口清单与测试记录 |
| P0.2 固定任务范围 | 确定支持语言/语法、项目单元、扫描清单、排除规则、导航任务及样例版本 | 可复用的输入与范围清单 |
| P0.3 固定验收口径 | 沿用P@10、入口、性能和审查指标；区分硬门槛、观察指标与待先导确定项 | 指标定义、适用条件和测量方式 |
| P0.4 准备标签与分割 | 冻结首轮导航标签来源；按仓库/缺陷家族分组，登记train/dev/封存来源和缺口 | 带版本的标签/分割初稿 |
| P0.5 拆任务与登记未知 | 给后续任务确定负责人、输入、产出、依赖；记录模型/预算、独立样本、平台等未知 | 执行台账与估算依据 |

**交付物**：《基线记录》《验收与范围清单》《任务及待决事项台账》。历史命中率、旧脚本退出0或旧测试通过，均不自动证明新契约达标；不为收集旧基线在宿主机加载目标项目工具或插件。

**完成条件**：输入、指标和现有缺口可追溯；P1调排序前导航评测口径已固定。暂时无独立样本或统计规模时，记录缺口及正式评估的前置任务，不编造标签、人数或通过结论。

## 四、P1 工作空间导航

**目标**：复用已有onboard与环境/索引补强，形成“打开项目 → 独立工作空间 → 阅读代码 → 运行分析 → 查看导航与任务”的本地网页闭环；CLI继续提供自动化。

| 任务 | 具体工作 | 预期成果 |
|---|---|---|
| P1.1 环境与子项目 | 只读发现运行时声明、锁文件、工作区和配置；区分声明/观测/未知 | 环境画像，能识别frontend等子项目 |
| P1.2 受控解析 | 使用来源/版本明确的工具链，不隐式加载目标包或继承注入选项 | 缺目标依赖仍可作静态分析，失败有原因 |
| P1.3 符号与图 | 完整作用域身份；调用/导入绑定分层；保留接收者、别名、候选及依据 | 同名定义不合并，猜测不进入确定图 |
| P1.4 缓存与完整性 | 失败不缓存为成功空结果；环境/工具链/配置变化按依赖失效；迁移旧缓存/索引版本 | 未改源码但环境恢复后能重试，增量与全量一致 |
| P1.5 输出与新验收 | 显示扫描/解析覆盖，修正P@10和退出码；性能包含实际报告输出 | 可复算导航报告，不以自洽代替语义正确 |
| P1.6 开发项目与任务试验 | 固定版本复测两个开发项目；先导验证入口、数据流、影响面等任务 | 失败分析及理解任务的初步证据 |
| P1.7 工作空间与API | 注册/重开canonical目录、独立配置/任务/结果、文件读取及worker生命周期 | workspace身份贯穿API与持久状态，源目录只读 |
| P1.8 浏览器工作台 | React/TS/Vite前端联本地API，项目列表、文件树、只读标签页、概览/环境、导航和任务历史/取消 | 联真实分析核心，不用mock结果冒充能力 |
| P1.9 UI与隔离验收 | 两工作空间同名文件、切换竞态、重启、stale、路径/来源/token、取消及真实浏览器流程 | 可复核的API/浏览器记录、截图与启动说明 |
| P1.10 统一文件访问策略 | API、浏览、静态索引、环境、worker与CLI统一AccessPolicy；Git/敏感/用户规则、硬链接多别名拒读、读前后权限及活注册表guard；任务与产物关联策略 | 本地实现完成并通过本机功能验收；exclude不读内容，local_only禁任何模型；model_eligible仍需授权；只接受fresh原文准备，外来衍生内容全拒，无真实transport |
| P1.11 权限UI、迁移与反例 | 目录预览与expected_version CAS确认，冲突409；旧workspace先确认，新workspace默认本地；所有策略变更保守失效全历史并清理受管产物，失败保持拒绝 | 本地实现完成并通过本机功能验收；浏览器旧内容与迟到响应校验、旧worker取消及CLI撤销guard已有实现，缓存按权限摘要隔离，全量回归已通过本机验收 |

**交付物**：工作空间注册与本地API、浏览器工作台、导航版本、环境/完整性报告、固定反例集、《导航验收报告》、增量/全量对照、API/浏览器证据、启动说明及先导任务报告；新增版本化访问策略、权限配置UI、旧workspace迁移状态和撤销传播记录。

| 验收项 | 条件 |
|---|---|
| 阅读顺序 | 适用任务P@10≥80%；Recall@K独立报告，不能替代P@10 |
| 入口 | 有有效金标时召回100%、精确率≥0.9；无适用入口的任务另行说明 |

| 页面与任务状态 | 旧项目迟到响应不覆盖当前项目；失败/不完整/取消/重启中断如实显示，旧快照变更标stale |

| 文件读取权限 | `exclude`在API/浏览/静态/环境/worker/CLI均不读内容、不hash/index/cache/记录内容日志；Git忽略嵌套及tracked命中、敏感默认、拒绝优先一致，仓库配置与`!`不能解除用户限制 |

**完成条件**：声明范围内的导航硬门槛与UI/API固定验收均满足，标签、原始计数及失败清单足以复核。工作空间开发预览可先使用，但不能据此标P1整体通过。两个项目只证明开发样本表现；缺独立评测时不能宣称跨项目泛化或真实理解效果成立。

## 五、P2 隔离执行与评测基础

**目标**：具备安全边界明确的执行手段和可独立计分的数据设施，先不替尚未实现的检查器宣布效果。

| 任务 | 具体工作 | 预期成果 |

| P2A.1 标签裁决 | 核对历史fix语义，构造已裁决bugs、规则负例clean、单列debt；记录未知与裁决依据 | 版本化数据卡和问题匹配准则 |
| P2A.2 分组与封存 | 按项目/派生关系/缺陷家族分割；冻结清单、评分器和访问记录 | train/dev/封存评测职责分离 |
| P2A.3 独立评分 | 实现一对一匹配、TP/FP/FN、未知、阶段流失和分层报告；用可人工复算的预测样例校验 | 可复算评分器，不接受候选自报分数 |
| P2B.1 最小runner | 按技术稿验收首个Docker/Linux后端：快照副本、结构化任务、可信镜像、权限/网络/资源限制、超时回收 | 仅在已验收任务与平台执行，不静默退回宿主机 |

**交付物**：数据及分割清单、评分器、runner能力声明、《隔离与恢复验收报告》、封存访问台账和动态用例证据。只在执行时生成这些交付物，不用空文件冒充已交付。

| 验收项 | 条件 |
|---|---|
| 数据与评分 | 标签有来源/状态，bugs与debt不混算；重复/未知/空分母样例计分正确；能从原始预测复算报告 |

## 六、P3 确定性审查与门禁

**目标**：形成不依赖模型判定的审查闭环，可靠地区分通过、阻断、不完整和错误。

| P3.2 Finding信任 | 草稿/报告模型分开；可信规则重算位置、事实、严重度与规则条件，绑定当前输入凭据 | 默认值、JSON和模型自报字段不能取得阻断资格 |

**交付物**：可运行的规则与scan/CI闭环、Finding/基线协议、指纹迁移说明、规则数据卡、反例及效果报告、发布/回滚记录。

| 验收项 | 条件 |
|---|---|
| 行为缺陷效果 | 在已声明且证据充分的适用问题集上precision≥0.85、recall≥0.70，报告TP/FP/FN、未知、样本和不确定性 |
| 政策与债务 | 单列规则违规和debt结果；仅实现复杂度/命名检查时，不能宣布行为缺陷recall达标 |

### P4 收口方案

**读清一条流程 → 用 CRAP 找一个值得核对的函数 → 讨论具体改法 → 对照复评结果。** 交付入口在已有对话与报告中。小样本功能闭环已交付。真实模型仍出现过格式失败和不可触发的测试建议，独立的带学与重构质量验收待做。见[小样本复测](execution/执行台账.md#p4-收口小样本复测)。

| 顺序 | 任务 | 交付与验收 |
|---|---|---|
| 1 | 建立一轮小样本基线 | 用可公开的 Python 样例找入口、追踪一条流程，并分别分析复杂但覆盖充分和覆盖不足的函数。人工记录四个任务所需的文件、行号及可接受结论。用真实模型试一轮并记录引用、遗漏、耗时和请求次数。真实项目试用沿用用户主动发送的授权流程。 |
| 2 | 从报告直接讨论具体函数 | 在报告行提供「讨论改法」，打开对应源码并填好可编辑的问题。服务端以当前话题的报告记录定位函数，核对文件摘要和访问权限，再按原预算取该函数片段。覆盖率数据和评分留在本地报告，模型根据本轮获准源码说明现状、建议改法或保留理由、取舍和验证方法。源码变更时提示重跑。 |
| 3 | 做一次改动前后的复评 | 在一个样例上完成改动、用同一测试范围重新收集覆盖率，再用已有报告并排核对同一函数的 CRAP、圈复杂度、覆盖率和行为测试结果。由开发者在测试环境执行改动和测试。覆盖率口径或测试范围变化时说明差异，缺失时保留 N/A。首轮产出一份可复核记录。 |

质量复测要求流程讲解回指源码并说明未知，函数建议明确优先补哪条路径、何时值得拆分、用什么断言确认行为。固定反例覆盖同文件有多个函数、源码变化、无覆盖率、仅限本地及撤销访问，已失效或未授权的取材不得发布或发送。复评保留两次报告、源码与覆盖率来源及测试结果，分数仅作维护风险线索。

**完成条件**：知识与证据生命周期闭环；指标只代表该变更集和作用域，不据单仓库经验形成跨生态通用规则。

## 十一、指标口径与封存时点

| 类别 | 采用方式 |
|---|---|
| 既定硬目标 | 沿用P@10≥80%、入口召回100%/精确率≥0.9、L1<30s/L2<3min、适用审查precision≥0.85/recall≥0.70、漂移检出率≥0.9 |
| 固定反例 | 按预先列出的输入与预期行为逐条判定；全部通过不等于所有未知输入均已证明安全/正确 |
| 观察指标 | Recall@K、绑定分类/金标正确率、候选阶段流失、实际理解效果、误阻断、准备与运行成本等，报告计数和范围 |
| 先导后确定 | 样本量、统计误差、独立审阅资源、模型与预算、动态任务限额、L3正式门槛；在正式测量前登记 |

统一遵守以下计分规则：

1. 无告警precision、无正例recall，以及入口相关空分母均为N/A，不折算为100%，不能支持验收通过。
2. P@10按前10项内唯一文件命中计；重复输出占位不重复得分。输出不足10项不能声称P@10通过；标签不足8项优先记标签不足。任务本身确实不适用时，须事先独立复核登记。
3. 未匹配/歧义金标、必要解析失败或预算截断不能靠缩分母消失；bug、规则负例与debt分开。
4. 性能计入实际输出，报告硬件、源快照、工具链及冷/热缓存；准备环境成本另报。增量一致性以同一目标快照的全量结果比较。
5. 开发循环只使用train/dev。现有两个项目是开发/回归项目，不能重新命名成独立holdout。
6. 不在每个阶段机械查询同一封存集。只有预登记的冻结发布候选或规则晋升点评估相应未启用批次，记录访问及可见反馈；利用结果修订后该批降为dev，下一次正式结论改用新批次或预留未启用分片。
7. 阶段通过只覆盖其已声明任务、规则、平台和样本；发布时保留未通过/不适用/未知事项，不汇总成“全部能力已验证”。
