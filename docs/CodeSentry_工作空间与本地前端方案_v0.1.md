## 一、产品目标与首版流程

**2026-11-08 当前界面**。左栏是项目与文件，中央是 Agent 对话和 CRAP，右栏只显示源码。文件权限和模型配置使用各自的设置弹窗。项目约束通过对话说明，旧的单独约束和反馈留在本地记录中。下文的面板与流程是历史设计，网页的使用方法以 README 为准。

**2026-11-02更新**：主界面以项目对话为中心。左栏提供学习路线和本项目话题，可切到文件树；右栏提供源码、项目约束、设计反馈及原有工具。左右栏独立收起、拖动调宽、保留宽度与可见性；专注模式退出恢复此前状态。具体实现、边界与预览对照见[本轮记录](execution/P4_项目对话与带学界面_20261102.md)。下面保留原静态工作台流程；不再以小型片段审查区代替Agent对话。

日常流程：打开项目并确认文件范围 → 配置模型 → 单独开启本项目自动取材授权 → 直接提问/追问 → 点击引用对照源码 → 补充项目约束或反馈。项目记录不跨空间复用，学习路线可跳转，不把“讨论过”显示为“已掌握”。原片段审查保留逐次精确预览。

CodeSentry的主入口调整为本地网页工作台。用户打开代码目录后，在该项目自己的工作空间浏览代码、理解结构、运行分析并查看结果；CLI继续服务自动化、诊断和CI集成。

已有流程：项目列表 → 选定/填写代码目录 → 创建或重开工作空间 → 文件树与只读代码阅读 → 运行静态分析 → 查看阅读顺序、环境、解析问题和任务历史。

首次创建或旧工作空间迁移在读取源码前增加“确认文件访问范围”；重开已确认工作空间使用已保存策略。模型服务及其可用范围继续单独授权。

| 界面区域 | 首版职责 |
|---|---|
| 项目列表 | 显示已打开项目、名称、路径与最近状态，创建或重新进入工作空间 |
| 文件导航 | 展开目录、选择文件、搜索或过滤可读文件；不把依赖产物与凭据当成默认代码阅读内容 |
| 中央阅读区 | 文件标签页、路径、行号和只读代码；点击导航结果可打开对应文件 |
| 项目概览 | 展示技术/环境声明、解析覆盖、入口候选、推荐阅读顺序及证据边界 |
| 分析与任务区 | 发起、查看和取消分析，显示排队/运行/失败/不完整及历史结果 |
| 后续能力 | M3完成后接入真实审查结果，M4完成后接入语义辅助；未实现能力不展示虚构成功、告警或聊天结果 |

首版代码区只读；补丁生成、验证及应用仍按P7处理。工作台实现不表示已具备完整IDE的编辑、终端、调试或扩展系统。

## 二、工作空间身份与生命周期

工作空间是用户授权代码目录及其分析状态的逻辑单元。它指向原始目录，不自动复制或改写源码；运行验证需要的隔离副本由P2 runner建立。

| 对象 | 目标合同 |
|---|---|
| workspace_id | 后端生成的不可混用标识，不由客户端文件名推断 |
| 源目录 | 注册时解析为规范绝对路径，按平台处理路径大小写及别名；相同canonical root再次打开复用同一工作空间 |
| 独立代码副本 | 不同目录、克隆或Git worktree使用不同工作空间；同一目录切换分支时保留工作空间并产生新的输入快照 |
| 配置 | 每个工作空间独立保存；任务入队时固定本次配置，之后修改不回写历史任务 |
| 任务与结果 | 均绑定workspace_id、任务id、源/配置/工具链身份；工作空间切换不改变已运行任务的归属 |
| UI状态 | 文件标签、展开目录、当前选择等按workspace_id保存，不能复用另一项目的缓存键或编辑器model URI |
| 重开与关闭 | 重开恢复该工作空间历史；关闭界面不删除源码，也不自动取消其他工作空间任务 |

注册表与任务元数据可使用本地SQLite，分析结果按工作空间/任务分目录保存。源目录、注册表、结果、日志与缓存的数据角色分开；原有需Git审阅的规则/基线JSON不被应用状态数据库替代。

默认状态目录在用户本地应用数据位置；开发与测试可以显式指定独立data_dir。状态不写入被分析项目，不自动提交或同步到云端。

## 三、隔离范围与信任边界

本版服务单个本地用户。工作空间隔离解决项目数据与上下文串用，不构成不互信用户之间的多租户权限隔离，也不代替操作系统沙箱。

| 边界 | 必须满足的条件 |
|---|---|
| API归属 | 文件、配置、任务、日志和结果请求均在已注册workspace下解析；通过另一workspace_id访问已有任务/结果要拒绝，不能回退到全局“当前项目” |
| 文件路径 | 只接受已注册root下的严格相对路径；拒绝绝对路径、穿越、编码绕过及符号链接/junction越界。拒绝已知凭据、.env、.git及不支持的二进制/超限文件读取 |
| 本地服务 | 默认绑定loopback；校验Host/Origin及会话token，不开放任意来源CORS；浏览器页面不能任意替用户注册目录或读取本机文件 |
| 前端资源 | 生产资源、代码阅读器及worker本地打包，不运行时拉取CDN脚本。源码按数据渲染，不执行其中HTML、脚本或仓库指令 |
| 任务执行 | HTTP层只负责调度/读取；重计算放固定可信worker，输入目录是数据，不作为可执行入口或模块搜索路径 |
| 目标代码运行 | 导入目标包、安装其依赖、测试收集和动态验证仍须通过已验收runner；打开网页或创建工作空间不构成执行授权 |
| 状态与留存 | 结果、日志和索引仍可能包含敏感信息；本地隔离、范围限制和清理策略同时适用，不能因“只存本地”声称无风险 |

工作空间id是关联键，不是鉴权凭证；本地服务令牌和请求来源约束用于防止其他网页访问本机能力，不能据此承诺防御任意已能运行本机代码的攻击者。

### 3.1 文件访问范围

**用户决定**：同时提供“完全排除”和“仅限本地分析”，在选择项目目录时配置，在工作空间设置中持续管理。两者是文件访问权限，不与“不解析”或“不参与重要度排序”的算法设置混用。

| 权限 | 本地文件阅读与确定性分析 | 本地索引/缓存 | 任何模型输入 |
|---|---|---|---|
| 完全排除（exclude） | 不读取内容，包括环境识别、哈希、差异检查、敏感内容检测 | 不新增或复用其内容及衍生信息；已有数据按下述撤销流程处理 | 禁止 |
| 仅限本地分析（local_only） | 允许工作台阅读、受控静态解析和本地确定性分析 | 可在本地工作空间保存，保持权限和来源标识 | 禁止，包括本地模型、云端模型、embedding/重排模型 |
| 模型可用候选（model_eligible） | 允许 | 允许，绑定来源与策略 | 仍需用户对具体模型服务、用途及数据范围授权；仅发送当前任务必要内容 |

新工作空间默认只启用本地静态能力。未显式启用模型并确认可用范围时，任何文件都不能进入模型上下文；选择目录不等于授权模型读取。首版同时提供两个限制选项，不把“仅限本地分析”推迟到后续版本。

2026-11-02更新：网页新建空间默认将未受限制的普通文件列为模型候选，使用可关闭的“普通文件默认允许模型取材”开关；确认访问范围后才生效，模型/对话仍需分别启用。显式`local_only`、`exclude`、Git与敏感排除优先级保持不变。已有空间保留原配置，升级须有具体项目及范围授权；本轮三个项目的批准、数量与策略版本见[升级记录](execution/P4_模型默认范围升级_20261102.md)。

**默认规则与优先级**：

1. 现有root、路径、链接/junction及资源限制先执行；常见凭据、`.env`、私钥等默认完全排除，首版不提供通过模型请求或普通包含规则解除这些限制的入口。
2. 默认开启“遵守`.gitignore`”。先计算Git规则内的嵌套与`!`例外，最终匹配忽略的路径按完全排除处理；即使已被Git跟踪也适用。这是CodeSentry的权限选择，区别于Git对已跟踪文件的行为。[Git官方规则](https://git-scm.com/docs/gitignore)
3. 用户额外排除规则与上述限制合并；冲突时完全排除优先于仅限本地分析，仅限本地分析优先于模型可用候选。模型可用范围只能在允许本地读取的范围内选择；Git的`!`不能解除用户排除或仅限本地分析。
4. 用户规则采用工作空间相对路径，可选择具体文件/目录或填写明确支持的匹配模式。提供命中来源与最终权限预览，不使用“最后一条允许”覆盖已有禁止。仓库文件和模型输出不能修改这些用户权限；未来导入仓库规则也只能提出收紧建议，扩大范围须由用户在可信设置入口操作。

首版Git规则来源限定为根目录及允许遍历目录中的嵌套`.gitignore`；不自动读取宿主全局Git配置、`.git/info/exclude`、子模块或工作空间外的规则文件。规则文件只在本地用于匹配，不自动作为模型上下文。`.gitignore`本身同样受禁读约束：若用户排除它，或遇到重定向、不可读及无法可靠匹配的规则，不能为了解析规则越过限制；受影响范围保守阻断并提示待确认，不能静默放行。Windows匹配处理大小写及规范路径别名，具有多个硬链接别名的文件保守拒读。需要读取的控制文件及其作用在确认页说明。

**界面流程**：选择目录后只枚举必要目录项并读取获准的忽略规则，确认前不预读源码、不自动分析或恢复旧源码标签。页面提供“额外排除”和“仅限本地分析”两组选项、路径/模式输入、生效预览与排除原因；权限按workspace保存。被排除路径可为本地配置预览展示必要名称，不显示其内容，不默认把这些名称、规则和原因发送给模型。新权限持久化成功后才开放文件读取和任务入口。

**统一执行与来源传播**：后端使用同一份工作空间访问策略约束文件树、单文件API、解析发现、环境配置读取、索引/缓存、后台worker、CLI、检索和未来模型出口，不能只在UI隐藏。CLI从匹配规范root的可信工作空间策略或用户显式指定的可信策略加载权限；缺少已确认策略时先完成范围确认，不能绕过网页权限直接扫描。目标仓库内的算法`policy.yaml`不自动成为扩大读取或模型授权的来源。每次实际读取或发送均重新校验当前权限；旧任务快照或旧缓存不能恢复已撤销权限。环境配置禁读时报告该条件未知或范围受限，不为补齐环境而读取秘密。

源码片段、符号/签名、调用边、摘要、Insight、模型回复/缓存、向量和检索结果均保留输入来源及权限。仅限本地文件产生的衍生信息同样禁止交给模型。混合来源结果按最严格权限处理；无法证明来源可分离时，整份结果仅在本地使用或隔离重建。模型上下文中的结构视图须由模型可用输入重算，或证明已与受限输入完全分离，不能简单删除原文后宣称无泄露。允许读取的普通源码仍可能含密钥，模型出口须做本地敏感内容检查；命中先阻止发送并提示处理，检测通过不承诺没有秘密，也不能为此扫描完全排除文件。

**策略版本与撤销**：工作空间策略拥有版本和摘要，任务、结果、缓存及模型请求固定其来源策略；有效忽略规则变化也使策略摘要变化。预览同时携带当前工作空间版本，提交时校验`expected_version`，冲突返回409并要求重新预览确认，避免旧的宽范围预览覆盖新限制。当前权限可进一步限制旧快照，收紧规则不是普通的“下次分析才生效”设置：

- 保存收紧策略时，先使服务端对受影响读取/模型出口立即拒绝，再取消旧策略在途任务，拒绝迟到响应写回；UI清除受影响预览、Monaco model及浏览器持久状态。
- 新增完全排除时，清理应用管理的受影响缓存、索引、结果、日志及衍生数据。不能准确分离来源时，隔离整份旧产物并重建；清理未完成或失败时保持拒绝并显示待清理，不继续提供旧内容。源文件本身不被删除或改写。
- 收紧为仅限本地分析时，可保留符合新权限的本地静态结果，但禁止其进入任何模型、向量化或模型缓存复用路径。放宽权限也不自动重放旧请求，仍按本次服务、用途及数据范围授权。
- 清理只覆盖CodeSentry管理的数据，不能保证磁盘安全擦除，也不能撤回已导出或已发给模型服务的数据；停止后续发送不冒充已撤销此前外发。

**旧工作空间迁移与完整性**：缺少已确认访问策略的工作空间，升级后先进入范围确认状态，禁止自动恢复源码内容、新分析及模型入口；确认后才按新规则恢复允许的数据。完全排除造成的缺失须在本地报告允许范围和限制，不把无法读取的配置/依赖当作已理解。未来审查必检范围受隐私限制时应记受限/不完整，不能借排除项宣称审查通过；导航质量评估保留冻结范围和原始计数，不因排除而调整旧GT得分。

本节已接入实际读取和工作台。升级旧库只增加权限元数据并置为待确认，不替用户确认范围；确认后才按当前策略处理受管历史。实现对权限变化保守地使整份旧产物失效并清理，暂不保留可证明分离的部分历史。模型输入准备只开放重新读取的候选原文，所有外部传入的摘要/图/旧结果均拒绝，尚无可信衍生构造器或真实模型调用。执行与验收见[P1.10–P1.11记录](execution/P1_文件访问权限验收.md)。

## 四、应用分层与技术选择

| 层 | 选择与职责 |
|---|---|
| 独立前端 | React + TypeScript + Vite；作为浏览器SPA消费结构化API，直接呈现分析核心结果 |
| 本地API | Python FastAPI；注册工作空间、读取授权文件、调度任务、返回结果及本地静态资源 |
| 分析核心 | 复用已有环境画像、受控解析、索引与导航；不另造一套前端解析器或让UI解析终端文本 |
| 本地worker | 固定可信程序执行分析，有界并发、输出、取消与回收；不等同目标代码runner |
| 持久状态 | 独立data_dir，元数据及结果按workspace/任务关联；服务重启后不能把未完成任务当成功 |

生产界面与API同源提供；开发服务器代理仅限显式本地开发配置。版本由实际安装与lockfile记录，不在方案中虚构已验证的依赖组合。

### 本地构建与启动

当前交付源码仓库，尚无安装包。Windows PowerShell下需准备Python 3.11及以上、仓库内`.venv`虚拟环境与Node.js/npm。若没有虚拟环境，先在仓库根目录执行`python -m venv .venv`，随后安装并构建：

```powershell
.venv/Scripts/python.exe -m pip install -e ".[dev,web]"
cd frontend
npm ci
npm run build
cd ..
```

在仓库根目录启动本地工作台：

```powershell
.venv/Scripts/codesentry.exe serve --data-dir .venv/workbench-data --open-browser
```

默认监听`127.0.0.1:8765`，浏览器打开`http://127.0.0.1:8765`。当前提供工作空间、只读代码阅读、静态分析、任务历史、DeepSeek片段审查及项目对话；不执行目标代码。模型设置与对话自动取材分别授权；长期密钥和项目问答启动说明见[README](../README.md)。TypeScript/JavaScript分析所需的受控工具链缺失时须显示解析限制。

示例状态存放于CodeSentry自身的`.venv/workbench-data`，须与被分析项目源码分开；省略`--data-dir`时使用用户本地应用数据目录。`--port`可更换端口，`--frontend-dir`可指定已有构建资源。`--dev-origin`仅供显式本地前端开发使用，生产同源启动不需要。

## 五、API与结果的最小合同

以下定义资源职责，精确字段/状态码以实现后的OpenAPI与前后端共享类型核对；两者不得各自推断一套不兼容协议。

| 资源 | 职责 |
|---|---|
| session | 为同源前端获取会话信息/令牌；令牌不写入目标仓库 |
| workspaces | 列表、注册、读取和修改允许的名称/配置；重复目录返回现有工作空间 |
| workspace/files | 返回该目录已允许的文件元数据；读取文件时再次检查路径、类型、大小及归属 |
| workspace/analyses | 创建分析、查询历史/状态/结果、请求取消；每项返回workspace_id与任务id |
| analysis/result | 带源/配置/工具链身份、static/resolved/observed层次、解析完整性、问题与导航结果 |

任务状态至少能区分排队、运行、完成、不完整、失败、取消和重启中断。分析完成只表示任务执行状态，不表示代码通过门禁；is_complete只在其声明范围内解释，不能当作语义全部正确。

历史结果保持原输入身份。代码阅读接口与任务快照须提供同口径摘要：现有解析文本哈希与原始文件SHA256不能直接互比。文件或配置已变化时标记stale；不能用旧结果行号悄然定位为当前精确证据。

## 六、前端异步与任务行为

1. 工作空间切换时取消旧页面的数据请求或校验请求代次；旧项目迟到的响应不能覆盖新项目的文件、概览或任务。
2. 所有查询缓存和代码阅读器model URI包含workspace_id；源路径相同但工作空间不同仍是不同文档。
3. 切换界面不等于取消后台任务，取消必须指定所属workspace与任务。排队取消、运行中取消和服务关闭均需明确状态与回收记录。
4. 服务重启后保留已有工作空间和历史结果，曾运行中的任务标记中断/不完整；不重放不明确的任务或伪装成功。
5. 页面要有空、加载、失败、取消及部分结果状态。错误说明告诉用户缺少什么或如何重试，不用假数据填满工作台。
6. 前端不提升来源信任，不能改写源/配置身份、P@10分母、批准基线或门禁结果。

## 八、最小验收矩阵

| 场景 | 通过条件 |
|---|---|
| 两个目录都含main.py但内容不同 | 文件、配置、任务、历史与结果均按workspace区分，不能串用 |
| 相同目录重复打开、不同worktree打开 | 前者复用workspace，后者独立；源目录未被复制或改写 |
| 打开/分析A时快速切到B | A的慢响应不改变B当前内容，后台任务仍关联原工作空间 |
| 服务重启 | 工作空间和历史可恢复，未完成任务明确中断/不完整，不伪装成功 |
| 源码/配置在分析后变化 | 旧结果显示stale，定位不冒充当前精确证据，支持重新分析 |
| 路径穿越、绝对路径、链接/junction及敏感文件 | 请求拒绝；异常不导致读取另一root或暴露凭据 |
| 非允许Host/Origin、无效token | 本机敏感能力拒绝，不能以CORS*绕过 |
| 排队、失败、取消与关闭 | 状态和日志一致，运行资源被回收，不误报完成 |
| 未安装目标依赖、未启用云端或未实现审查 | 静态结果按能力显示；不运行目标、不外发源码、不生成虚假审查通过 |
| 浏览器实际操作 | 创建/重开、切换、读代码、发起分析、查看结果/取消均联真实后端；页面不依赖外部CDN |

新增权限验收（P1.10–P1.11，独立结果见[文件访问权限记录](execution/P1_文件访问权限验收.md)；不得以既有278/19/3项通过替代）：

| 场景 | 通过条件 |
|---|---|
| 新建与旧空间首次确认前 | 目录/规则必要读取与源码内容读取分开；无自动源码预读、分析或模型调用 |
| 完全排除文件及目录 | 对阅读API、环境识别、索引/哈希、敏感检测、worker、CLI、缓存恢复逐项注入读取监测；禁止内容读取成功次数为0 |
| 仅限本地内容 | 本地阅读/静态索引可用；原文、路径/签名、摘要、图、检索、向量和旧模型产物不能绕道进入任何模型入口 |
| Git规则及权限冲突 | 根/嵌套/`!`、已跟踪匹配路径、无Git仓库、大小写/分隔符等固定用例符合声明语义；Git例外不能解除用户限制 |
| 忽略控制文件禁读/异常 | 不读取其内容或哈希；受影响范围阻断并说明，不能默认为允许 |
| 仓库/模型伪造允许配置 | 不改变用户权限；两个工作空间规则各自独立，不能借同名路径复用授权 |
| 运行中收紧权限 | 在途任务取消、迟到结果拒绝、旧预览清除；缓存/历史/日志无法分离时整份隔离；清理失败也不能恢复读取或发送 |
| 仅限本地后再放宽 | 本地合法结果可留；未重新获得模型授权时无重放、无自动上传；重开后保持已确认策略 |
| 内容检测和完整性 | 普通允许源码内的秘密样例在模型出口被本地拦截；不为扫描秘密打开完全排除文件；受限范围不记完整审查通过 |

模型服务尚未接入时，用具名模拟出口和调用监测验证禁止发送，仅记录策略/调用边界测试通过；P4接入真实模型或embedding后对实际出口再次验收，不把模拟出口称为真实服务已验证。

验收按固定反例逐项记录。跨工作空间错配、越界读取、未授权源写入、虚构成功或原始模型结论阻断的固定反例成功数为0。接口、队列、分析、输出和页面渲染成本分层记录；新增UI性能硬阈值待先导测量后登记，不复用CLI耗时冒充完整页面交互时延。

240项测试与296个文件解析完整是接入前的分析核心证据，此前P@10为50%/60%。工作台接入权限前的278/1跳过、19前端、3浏览器见[历史工作台验收](execution/P1_本地工作台验收.md)；权限交付时的359/1跳过、26前端、4浏览器见[文件权限验收](execution/P1_文件访问权限验收.md)。最新启动角色、证据跳转、分支阅读路线及权限绑定开发对照见[本轮导航复测](execution/P1_导航证据与阅读路线复测.md)，P1正式质量验收仍未通过。本地启动方式见第四节；模型范围设置在P4实际接入时提供，当前没有真实模型调用。
