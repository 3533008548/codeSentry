## P2 这次做什么

P2A 先交付开发工具：从可信标签和原始预测独立复算计数，检查分组泄漏。示例全部为合成元数据，不创建“已裁决真实缺陷集”，不把两份开发项目变成独立封存集。

离线评分 `evals.review_scoring` 固定问题身份和允许行号/符号范围，用最大一对一匹配计数；相同预测不能取得第二次命中，额外已知问题告警记重复误报。bug 与 debt 分开，clean 只指所声明规则/范围的已审负例；范围外或待裁决预测保留 unknown，空告警的 precision 和空正例的 recall 为 N/A。按项目、语言、规则与版本分层，原始逐条匹配可复算。报告保留标签、预测、匹配契约和评分器SHA256，拒绝候选自报分数及holdout运行。unknown存在时只报告已裁决部分计数，不把其比例宣传为总体质量。

纯合成评分样例：

```powershell
.venv/Scripts/python.exe -m evals.review_scoring --gold evals/fixtures/review_gold_v1.json --predictions evals/fixtures/review_predictions_v1.json --output .venv/p2-score-demo.json
```

退出0只表示成功复算开发数据，不表示检测效果通过；输入/输出或契约不可用返回2。当前合成样例得到bug TP2/FP2/FN1、unknown预测2，debt TP1/FP0/FN0，clean误报1；这些是计数反例，不是审查器精确率/召回率实测。

分组审计 `evals.split_audit` 将同一仓库/派生组、具体缺陷谱系及显式派生关系合并为传递组，拒绝跨 train/dev/holdout 分配。`defect_family` 指同一缺陷及复制/修复变体的谱系，不是宽泛的 CWE 类别。缺失谱系、缺少派生来源、空数据以及使用过反馈的 holdout 都不能记为有效分配；已知开发项目不能转称 holdout。它只能核对声明，不能自动发现未声明的复制关系或通过改名字证明独立性。

本轮离线评分与分组工具不构成 OS 级封存隔离，也不执行候选代码。P2A.1 的真实标签裁决、P2A.2 的独立身份/封存访问控制、阶段流失统计和统计规模登记继续待做；P2 整体尚未完成。

运行纯合成分组样例（输出必须是新文件）：

```powershell
.venv/Scripts/python.exe -m evals.split_audit evals/fixtures/review_split_synthetic_v1.json --output .venv/p2-split-demo.json
```

退出0仅表示声明的分组检查无问题；退出1表示发现串组/未知等问题；退出2表示输入或输出不可用。输出中的 `isolation_verified=false`、`label_truth_verified=false`、`formal_acceptance.passed=false` 均不会被合成样例改为通过。
