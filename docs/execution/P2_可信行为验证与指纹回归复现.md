## 可信行为检查

原始执行后端仍把`test`退出0记为`not_verified`，断言数保持0。新增适配器对每个必测用例计算两项明确的宿主检查：实际退出码为0，以及原始合并输出的SHA256与可信计划相符。检查数由宿主计算，不读取目标自报的tests/pass/JUnit计数，不将这些检查数称为目标Python断言执行数。

`TestPlan`固定用例ID、argv、工作目录和预期摘要。加载入口只接受操作者明确选择的源码目录外文件，拒绝重复键、额外字段、链接/reparse、多硬链接、文件身份或内容漂移。实际开始验证时，再拒绝计划位于真实源码根或容器挂载的输入副本中，避免误把答案交给候选。

每个必测用例独立运行容器，执行前后、执行期间和最终发布前核对源码访问权限、快照、计划、镜像和预算。全部必测用例与两项检查完整且通过，验证结果才可为`passed`。超时、取消、工具错误、非零退出但缺少完整输出证据、未执行、截断、清理未完成或身份漂移均不能通过；它们也不能被当作已证明的业务缺陷。即使某个用例局部通过，最终整体证据失效时仍须拒用。

`BuiltinTaskPolicy`和准入记录只绑定宿主已经选定的固定开发任务，不从候选报告恢复权限。摘要不是签名、独立OS身份或Finding阻断凭据；同一可信Python进程内仍由调用方负责策略来源。当前开发入口只选择内置复现材料，没有外部项目路径、任意命令或自选答案参数。

## 复现材料与依据

选择CodeSentry自身的legacy指纹模块，冻结原始文件与Git来源，复制到独立开发样例。旧归一化取前12个非空行，也对字符串内部的空白做折叠。技术定稿§3.3.2要求证据覆盖完整依赖内容并保留字符串语义，因此固定以下三个行为检查：

| 必测用例 | 预先固定的成功条件 |
|---|---|
| 第12行后改变赋值 | 同一规则/符号的两个内容指纹应不同 |
| 字符串内两个空格改成一个 | 字符串值不同，指纹应不同 |
| 完全相同片段 | 指纹应稳定相同 |

`before`逐字节来自记录的原模块；`fix_candidate`只在样例副本中让归一化保守保留完整原始片段。两份输入都仅有模块与行为driver；计划、预期摘要、Git来源和数据卡留在宿主，未复制到容器。driver只输出实际观测布尔值，预期条件由容器外检查。

候选保留legacy SHA-1 API，格式/注释变化也可能使其指纹变化。它没有解决P3完整的身份与证据分离、配置/环境依赖、重复锚点、版本前缀或批准基线迁移，不能按本轮三项检查就合入生产替换旧实现。

## 运行与归因

运行入口使用已经准备的固定官方镜像、相同计划和相同资源预算，分别为原始版本和局部候选创建独立副本，不在脏工作区应用或反向应用补丁：

```powershell
.venv/Scripts/python.exe -m evals.fingerprint_verification --output .venv/fingerprint-reproduction-new.json
```

输出文件必须不存在。只使用本地已有的固定镜像，不自动拉取，不开启联网安装。缺镜像或后端、环境/计划检查失败时不能证明复现；修改镜像、计划或预算也不能继续沿用原对照结论。

除“原版本验证失败、候选验证通过”，对照还要求所有进程实际执行且退出0、三个检查全部完成、全部回收，以及相同计划/镜像/预算/架构。原版本的输出必须精确等于预登记的“两个false、一个true”观测摘要；任意警告、崩溃或输出格式变化不算指纹问题复现。

这里验证的是现有legacy指纹与已定契约之间的窄范围回归，不证明已有生产门禁漏阻断，也不代表独立审阅的真实bugs集建立。数据卡仍为dev、`label=unknown`、独立人工裁决pending；运行证据单独归档，不回写冻结数据卡或制造人工批准。

## 平台修复与范围

测试暴露Windows同一文件的路径查询和打开句柄查询在ctime字段上的差异。依据本机最小文件实测，句柄核对改用一致的设备/文件ID、大小、mtime、类型和链接数；路径读前后仍固定完整元数据与内容摘要，没有删掉关键身份或别名检查。初次失败的XML保留，修复后再跑完整回归。

本轮没有读取或执行Research Agent、Knowledge Loop的业务代码、依赖或测试，没有真实模型发送。网页仍是只读静态工作台；任意用户项目的执行、pytest/unittest收集、联网依赖安装和Windows/Electron后端尚未开放。
