## 本次裁决

用户在查看上一轮复现说明后，确认“第12行之后的代码变化”和“字符串内部空格变化”这两项为开发缺陷。确认范围是当前完整语义证据契约下的CodeSentry legacy指纹问题，不修改生产实现、不批准基线迁移、不算独立封存评估。

确认意见单独存为[操作者裁决记录](../../evals/adjudications/fingerprint_owner_20261028_v1.json)，绑定原复现报告、计划和来源描述的SHA256。审阅者记录为本对话用户/项目所有者，`independently_adjudicated=false`；没有将操作者声明当作身份认证。原始待裁决数据卡和unknown历史保持不变，新标签只进入新的开发数据版本。

正式产物见[新开发数据卡](../../evals/datasets/fingerprint_dev_v1/source_card.json)、[gold](../../evals/datasets/fingerprint_dev_v1/gold.json)与[数据清单](../../evals/datasets/fingerprint_dev_v1/manifest.json)。本次确认不覆盖P1的关键文件/入口标签，也不授予执行用户项目的权限。

新版本只含原始代码快照的一个case、两个唯一已确认问题。问题位置来自冻结源码的具体语句；作用域是partial，未列出的告警仍为unknown。相同输入稳定性对照不自动成为clean样例，候选通过三项行为检查也不等于对所有规则/范围审阅为clean。

## 可复算的开发基线

本轮不捏造尚未实现的检测器命中。用明确标注为non-detector reference的空预测检验新数据与评分器连接：空预测应得到TP0、FP0、FN2，precision为N/A、recall为0。评分命令退出0只表示成功完成计数，不表示检测效果通过。

数据集、确认意见、来源快照、复现证据、匹配契约和评分器实现均通过摘要关联。产物只写入新目录，已有版本与报告拒绝覆盖；不以看到得分后修改标签、分母或匹配范围。

实际计分与预期一致，见[空预测参考报告](../../evals/reports/p2_fingerprint_dev_empty_reference_20261028.json)。两项问题位于冻结`normalize_snippet`的34、35行；[评测协议](../../evals/contracts/fingerprint_dev_reference_v1.json)在运行计分前固定，明确没有执行检测器，不将此协议当作独立holdout统计预登记。

## 访问与反馈账本

账本保存批次来源组/具体缺陷谱系、冻结输入、评分器与预登记协议，以及候选版本、评估开始/完成、报告摘要和反馈释放/访问/使用记录。事务与唯一事件ID防止并发重放；事件链可检测意外修改，但同权限数据库所有者仍能重写整条链，不能称为不可篡改凭证。

使用过封存反馈修改候选时，相关批次必须降为dev；共享来源/谱系的关联批次不能通过改名重新当作新holdout。已参与开发的Research Agent、Knowledge Loop和CodeSentry样本不能转成独立封存集。账本只验证已声明关系，无法发现未声明的复制来源。

这是操作者管理的本地元数据流程，不读取gold、不运行候选、不发送消息，也不设置Windows账号或ACL。`os_isolation_verified=false`与`holdout_evaluation_ready=false`继续保留；评测入口仍拒绝holdout实际计分。只有独立身份、挂载/文件权限与真实执行边界另有证据时，才能声明封存隔离。

本轮只登记已暴露的指纹dev批次与空预测参考评估。合成测试覆盖holdout反馈降级流程，不把合成批次包装成真实独立数据。

实际账本含5个事件：注册dev批次、开始参考计分、完成计分、向本地操作者开放结果、记录操作者读取。结束状态为`finished`，但检测效果资格的`outcome=incomplete`，没有将空参考记为检测器通过。记录见[本次只读导出](../../evals/reports/p2_dev_registry_20261028.json)；数据库在`.venv/p2-reference-ledger-20261028.sqlite3`。后续数据库可追加事件，历史状态以导出中的事件和head_hash为准。消费者须使用`effective_partition`，不能把保留的历史注册partition当作当前资格。

需要本地复算时使用新目录/文件：

```powershell
.venv/Scripts/python.exe -m evals.fingerprint_dataset --receipt evals/adjudications/fingerprint_owner_20261028_v1.json --reproduction-report evals/reports/p2_fingerprint_reproduction_20261028.json --output-dir .venv/fingerprint-dev-new
.venv/Scripts/python.exe -m evals.review_scoring --gold .venv/fingerprint-dev-new/gold.json --predictions .venv/fingerprint-dev-new/predictions.json --output .venv/fingerprint-empty-new.json
.venv/Scripts/python.exe -m evals.sealed_registry inspect .venv/p2-reference-ledger-20261028.sqlite3 --output .venv/ledger-inspection-new.json
```

## P2交接范围

| 项目 | 已有开发能力 | 正式能力的限制 |
|---|---|---|
| P2A.1 数据裁决 | 真实来源副本、确定行为对照、用户确认的两个开发问题、版本化新标签 | 样本很少；非独立专家/封存裁决，不支持总体质量结论 |
| P2A.2 分组与封存 | 全局声明分组审计、反馈账本和降级流程 | 未验证独立OS身份与封存数据访问控制 |
| P2A.3 独立计分 | 一对一匹配、未知与空分母、分层及阶段流失、固定输入复算 | 新开发样例不等于已完成检测器precision/recall验收 |
| P2B.1 最小执行后端 | Docker/Linux固定任务、只读快照、限额、取消/超时/输出限制与回收 | 不支持任意平台/恶意仓库/联网安装/目标Dockerfile |
| P2B.2 候选与答案 | 实际任务只挂输入，预期与评分留在宿主，拒候选自报成功 | 操作者/提案/封存评估的独立身份仍待建设 |
| P2B.3 动态复现 | 真实CodeSentry来源副本原版失败、局部候选通过，固定环境与宿主行为检查 | 不扩大到用户业务项目、pytest/unittest收集或通用任务授权 |

因此P2按**开发设施已交接、正式独立评测待验收**收口。原指标、失败和未知保留；不将进入后续开发写成P2正式验收通过。
