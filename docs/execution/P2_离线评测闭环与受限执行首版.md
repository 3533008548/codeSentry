## P2A 一次评测闭环

`evals.review_run`读取可信操作者显式提供的run清单，固定gold、原始预测、匹配契约、完整分割计划和阶段记录五份输入的路径及SHA256，同时记录三个评测实现的摘要。运行前后核对身份与内容，不接受候选自报的分数或通过状态，输出拒绝覆盖旧报告。

分割审计覆盖完整train/dev/holdout计划；只加载本次train/dev分区的gold，要求gold恰好覆盖该分区全部样本，并核对仓库组/缺陷谱系。其他分区只有分组元数据，不读取其gold。相同仓库、具体缺陷谱系或派生关系经传递合并后不得跨集合；反馈暴露的holdout拒绝。初版仅含当前分区的v1记录保留为历史；v2才展示全局计划检查，不能用局部审计宣称全局隔离。

候选阶段为generated → budget_admitted → judged → accepted → verified → final；用原始候选ID与固定预测位置计数，集合只可缩小，最终内容必须与原始候选一致。每阶段重新做最大一对一匹配，按唯一适用问题计算召回；bug/debt、项目、语言和规则版本分别报告。deterministic/explore不并入本次semantic通道。

固定合成样例检查7项分割元数据，评分其中5个dev案例，候选数12→11→10→9→8→7；bug命中由3/3降至最终2/3，debt独立为1/1。它们用于证明计数能显示流失，**不是审查器或模型效果测量**。阶段记录来自声明，`execution_verified=false`；没有据此证明模型运行、目标源码复验、人工标签正确或OS封存隔离。

## P2B 内容快照与执行边界

`prepare_snapshot`只复制可信任务显式列出的文件，要求明确文件数、单文件和总字节预算，且输出在源码目录外。逐项使用统一AccessPolicy；排除、凭据、链接/硬链接别名等必要输入不可读时整次失败，不悄悄缩小任务。复制后二次读取检测常见源码漂移，manifest与实际挂载的files目录分开。它不是原子文件系统快照，不承诺抵御任意ABA并发改写，也不声明原项目之后仍与快照相同。

快照检查核对活权限指纹和副本字节身份；本轮执行入口持续传入`SourceSnapshot.check`。权限撤销或副本变化即中止。失败清理按本次创建文件的身份逐项删除，拒绝递归清理未知/被替换内容，失败明确`cleanup_pending`。这些副本属于操作者本地导出，不自动撤回后续另存的副本，也不授权任何模型使用。

Docker后端只接可信结构化argv、工作目录、已准备快照、不可变镜像引用和预期image ID；不执行宿主命令，不支持远程Docker、自动镜像拉取、目标Dockerfile、安装依赖、额外挂载或自动测试发现。只读绑定`/input`，固定bootstrap复制到有界tmpfs `/work`，再用非root身份运行；输入无宿主依赖与凭据。首版快照不保留POSIX执行位，合成任务显式指定解释器。

启动前检查Linux/native架构、镜像身份和后端对内存/交换/进程/CPU限额的支持，创建后核对实际容器配置再启动，结束后再核对。配置包括只读rootfs、无外网、清空capabilities、禁止提权、独立命名空间、无healthcheck/restart以及无daemon持久日志；输出只作有界捕获和基础脱敏。容器配置和本机合成反例只支持本次声明范围，不构成任意恶意公开仓库的安全保证。[Docker create](https://docs.docker.com/reference/cli/docker/container/create/)、[Docker安全边界](https://docs.docker.com/engine/security/)

执行结果区分未运行/后端不可用/平台不支持/环境错误/失败/超时/取消/通过。`probe/build`只有满足可信预期输出摘要才可通过；`test`退出0仍为`not_verified`，当前断言数0，不能证明测试验证成功。超时、取消、输出超限都进入回收；只接受精确绑定本次容器名的不存在响应来确认删除，Docker断连不算清理成功。未确认回收时保留`cleanup_pending`，不发布通过。
