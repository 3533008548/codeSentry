## 已实现的行为

| 范围 | 本轮结果 | 能力边界 |
|---|---|---|
| Finding信任 | 默认unknown、confidence=0、verified=false；模型草稿与报告模型分开，可信规则重算并绑定当前输入 | 报告字段、哈希或复制不能取得进程内资格；最终gate未实现 |
| v2内容指纹 | SHA-256分别保存身份、完整证据与组合摘要，保守保留全部原文/字面量/指令 | 格式变化可能使证据变化，不追求未经证明的语义等价 |
| 基线迁移 | 只读诊断与待复核建议，保留问题数和旧记录，忽略JSON自报approved | 没有生效豁免或写active基线的接口 |
| 首条静态规则 | Python函数物理行数策略债务，只报告预览 | 不标行为bug，不进入bug precision/recall，不得阻断 |
| CLI集成 | 显式`scan --preview`，按统一权限读取，完整性/预算/源漂移有状态 | 默认scan仍关闭正式门禁，浏览器审查页尚未接入 |

本轮没有读取或运行Research Agent、Knowledge Loop的业务源码/依赖/测试，没有模型发送。真实项目复测仍须沿用各自访问范围；模型候选范围与执行授权不因P3功能自动扩大。

## 结论资格

`Finding`公开字段属于报告数据。手填`source=deterministic`、`confidence=1`、`verified=true`，或加载一份历史JSON，都不构成资格。对象的Pydantic/Python复制、pickle和其他上下文也不能转移原来的资格。

可信宿主显式选择规则实现与版本，通过AccessPolicy固定完整文件及显式依赖、当前权限和策略，再运行规则重算位置、原因、级别、事实和提取数据。`VerificationContext`只识别自己的原始Finding对象及完整字段快照；观察到对象、输入、依赖、权限、规则实现、闭包参数或上下文漂移后，旧资格失效。缺依赖和工具错误保留不完整，不推造成代码问题。

两条入口明确分开：`evaluate()`独立运行已选确定性规则，可以生成新的确定性结果；`verify()`回验任意外来草稿/报告，只返回没有阻断凭据的新警告。LLM/Explore保留来源，外来Deterministic/Unknown报告标为Unknown；模型叙述不会因位置相符被盖上确定性印章。模型输出也不能删除独立确定性通道的结果。

`can_block(context)`仅表示当前原对象、当前输入和已经准入的规则满足最低资格，还不是最终门禁。正式gate仍须检查可信策略、必检完整性、严重级别和批准基线。当前生产规则`approved_for_blocking=false`，全部预览结果不可阻断；单元测试里的准入规则是工具自有反例，不代表生产已启用阻断。

该机制是可信宿主进程内的契约，不对已经能执行任意宿主Python的调用方提供OS隔离。候选代码、插件、测试收集等仍只能走另行准入的runner。

## 指纹与迁移

新指纹把问题身份与本次证据分开。身份包含规则/版本、仓库文件作用域、完整限定符号、结构锚点和出现序号；复制问题保留独立出现次数。证据包含完整原文、原始字节摘要、度量事实、依赖（API可显式表达缺失）、规则实现、策略、分析器、语言/归一化版本、配置与环境。

源码采用保守raw方式，不再截取前12行、不折叠字符串内部空白，注释/抑制指令也完整参与。生产函数已通过第12行后变化、字符串内部空格变化和相同输入稳定性回归。`compute_fingerprint`兼容旧调用签名但返回v2组合摘要；其legacy兼容模式带未指定作用域/版本标记，可信规则使用typed上下文接口。索引/缓存的`content_hash`仍保留原SHA-1，不能把两种哈希用途混为一谈。

旧`sha1:`与v2不兼容，没有自动继承豁免。`propose_baseline`即使发现完全相同的v2输入也只生成待复核建议；重复/歧义身份、证据变更、旧版本与未知版本都保留记录和待审状态。JSON写`approved=true`不会生效，没有自动批准迁移、写active或应用补丁。

P2的旧源码、局部候选、unknown原卡、用户确认的新dev数据及所有历史报告保持冻结。它们描述旧版本快照；本轮没有为了生产修复后得分变化去改旧答案或分母。原本用“当前生产等于旧fixture”核验的测试已改为验证记录的Git blob，避免把历史来源误当永久当前状态。

## 首条规则与预览

规则`python.function_length@1`计量从def/async def到AST最后语句结束行的物理行数，区间内空行/注释计入；装饰器和AST结束后的尾随空白/注释不计。方法、async和嵌套函数分别报告，重复定义保留独立身份与次数。它是策略债务，不是已证明行为缺陷。

默认开发阈值80行，可以通过本次可信CLI参数设置；不声称80是经实验得出的最优阈值。预览不加载目标仓库的算法配置来放宽策略，也不加载目标模块或第三方插件。

```powershell
.venv/Scripts/codesentry.exe scan /path/to/project --preview --max-function-lines 80 --confirm-access --json
```

已注册工作空间复用确认范围；工作台使用自定义数据目录时增加`--workspace-data-dir .venv/workbench-data`。`--confirm-access`仍不能绕过已经注册空间的待确认/清理状态。

预览专门使用非门禁退出状态：3表示完成只报告预览或没有适用输入，1表示不完整，2表示输入/权限/工具不可用。默认不带`--preview`的scan继续返回2。JSON始终`gate_status=not_evaluated`，不存在本轮CI pass/block结果；零Finding也不能解释为审查通过。

范围为获准Python文件（`.py/.pyi`）；其他语言只计未评估数量。默认限额2000次文件尝试、单文件2MiB、总输入预算32MiB；失败读取保守保留预留字节计账，不因失败退款绕过预算。全部排除、空输入、解析失败、深语法异常、限额与源码清单变化均显式保留状态。

扫描前固定声明文件清单，输出前重新枚举并核对每份已读源码，包括没有Finding的文件。已观察到的变化会标不完整并丢弃对应旧证据，权限变化则丢弃整个预览。它不是原子文件系统快照，不承诺捕获任意ABA并发改写。
