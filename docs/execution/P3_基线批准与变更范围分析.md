## 批准基线

在工作空间“审查预览”中完成一次审查，点击“生成基线复核提案”。提案展示每项问题；用户勾选并填写理由后，点击“批准选中项入基线”。批准记录可刷新恢复，也可填写理由撤销。

生成和批准前，服务端都重新运行同一静态规则，核对完整源码清单、原始字节摘要、全部问题、覆盖情况和策略。只有完整且仍与原报告一致的输入可以复核；新问题、代码变化、不完整报告和旧工具报告须先重新审查。动态生成时间不作为语义证据差异，其余字段保留校验。

批准记录保存在工具状态目录的`baselines.sqlite3`，不写入目标项目；该状态目录须位于被审项目之外。每条批准绑定工作空间、规范目录、当前权限版本、工具及规则策略，并保留问题身份/完整证据、审阅人、理由、时间与版本。审批/撤销使用工作空间版本校验，旧页面或并发操作不能覆盖新决定。审批失败不自动重试。

审阅人记录为当前本地用户`local_user`，不声称已核验独立OS身份。已有进程内任意执行权限的宿主调用者不在这层隔离边界内。仓库文件、导入JSON、旧`sha1:`及模型自报批准均不能获得当前记录的权力；旧迁移建议继续只读，须对当前v2问题逐项重新批准。

新报告逐项标注精确批准匹配、新问题、证据变化或歧义。只允许一对一的当前v2身份及完整证据匹配；复制、移动、重命名或证据变化不自动扩展批准。无关文件变化不会仅因报告整体摘要变化而抹去其他文件仍完全相同的批准。所有原问题保留，不因批准而隐藏；当前没有正式门禁豁免执行，仍显示“门禁未评估”。

旧报告上的批准标记仍描述那次报告快照，须结合当前源码过期提示阅读。同一身份已有批准时，先显式撤销旧决定，再批准新的证据，不累积成多个自动豁免。

权限变化会先关闭旧范围读取，取消旧任务并清除含内容的提案、批准记录和历史输出。只保留不含路径、理由原文或指纹的最小审计事件；清理失败继续保持访问关闭。

## 变更范围

左侧“变更范围”提供三种显式比较：

| 模式 | 比较内容 | 范围 |
|---|---|---|
| 工作树（默认） | HEAD或指定提交 → 当前磁盘 | 包含已暂存、未暂存和未跟踪文件，记录净变化与所在层 |
| 暂存区 | HEAD或指定提交 → index | 使用暂存内容，不用磁盘内容冒充暂存证据 |
| 两提交 | 显式base → 显式target | 不混入脏工作树，不自动选择merge-base或获取远端 |

提交引用首版仅支持`HEAD`或完整提交SHA。缺少对象/基点、非法引用或无法覆盖的仓库结构明确报告未完成/不可用，不回退`HEAD~1`。两提交模式是本地显式比较，尚不提供PR/CI merge-base选择合同。

Git只读取必要树、索引和获准对象；先经当前统一权限过滤路径，再读取对应历史blob或磁盘内容。不加载目标仓库可执行配置、外部diff/textconv、过滤器、钩子或目标代码；不做自动fetch/reset。首版保守拒绝链接式Git目录、linked worktree、浅克隆和外部对象替代路径。重命名/移动按删除加新增保留两侧，不用相似度提前读取禁读内容，也不据此继承基线。

比较采用未经过Git过滤器的原始字节；换行符/编码差异也可以列为变化，不承诺与启用仓库过滤规则的`git status`输出相同。报告明确记录这一口径。

实现核对的官方合同：[树元数据](https://git-scm.com/docs/git-ls-tree)、[索引元数据](https://git-scm.com/docs/git-ls-files)、[原始对象读取](https://git-scm.com/docs/git-cat-file)、[提交引用校验](https://git-scm.com/docs/git-rev-parse)、[进程环境](https://git-scm.com/docs/git)、[配置来源与include](https://git-scm.com/docs/git-config)。实际验证的宿主Git为`2.54.0.windows.1`，工作进程由宿主显式传入仓库外工具路径，不复制整个宿主PATH。

影响面是文件级Python静态导入关系，分别在变更前、变更后建图。删除从旧图找存活依赖方，新增/修改从新图查找；配置变化保守扩大到获准范围。调用关系、动态导入和其他语言不声称已评估，不能把导入候选当作完整运行影响。预算、解析失败、未支持文件、排除与截断保留状态，不用Top-K冒充完整覆盖。

源码跳转使用报告after侧的原始字节SHA-256。暂存/提交内容与当前磁盘不同会提示过期；删除项只显示历史路径。导航、审查、变更三个结果分别保留，权限和任务取消机制共用。

CLI保留自动化入口：

```powershell
codesentry changes /path/to/project --confirm-access --json
codesentry changes /path/to/project --comparison staged --confirm-access --json
codesentry changes /path/to/project --comparison commit --base <base_sha> --target <target_sha> --confirm-access --json
```

已注册工作空间须复用原权限，使用自定义状态目录时传`--workspace-data-dir`。完成只报告返回3，不完整/不可用返回1，参数/权限错误返回2；都不是正式门禁成功码。

## 验证与阶段边界

本轮使用工具自有合成Git仓库及源码，不读取或执行Research Agent、Knowledge Loop的业务代码，也不调用模型。测试与页面证据单独归档，旧P1/P2标签、冻结样例及上一轮P3报告保持不变。

完整Python回归1182通过、2跳过，197.63秒；跳过仍是Windows身份不具备普通symlink权限的两个用例，hardlink/junction实际运行。基线核心35项专项与真实接口4项已通过；变更核心41项均进入最终完整回归。真实接口初次3通过/1失败为受控工作进程缺少Git定位，显式工具路径修复后4项通过，初次记录保留。

前端最终57项单元测试及构建通过；真实浏览器9流程全部通过、无跳过或重试，75.77秒。首次浏览器8通过/1超时，原因是页面在新报告运行时读取基线得到未就绪状态，同一任务完成后没有重读；修复为就绪后自动读取只读状态，审批写入仍须显式提交。初次JSON、截图、上下文及trace保留，前端55/56/57项各轮原始输出分别归档。

独立复核的实际反例已修复并保留测试：`from pkg import leaf`的子模块影响遗漏及删除后的未知依赖、Git字面路径规范化与排除冲突输出、切换审查记录时操作按钮持续忙碌。跨记录操作完成后的最新批准标记仍可手动刷新，版本冲突时必须核对后重试，不自动重放写操作。
