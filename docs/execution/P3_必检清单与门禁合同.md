## 现在可以使用

网页左侧“门禁检查”可查看只读必检清单，显式运行后查看每条规则的执行、准入状态和缺项。导航、审查预览、变更范围、门禁四类报告分别保留。任务完成仅表示报告生成，不等于门禁通过；旧报告是其输入快照的历史判定，不能当作当前代码的通行证。

CLI使用显式入口：

```powershell
codesentry scan /path/to/project --gate --confirm-access --json
```

已注册项目复用原文件权限；工作台使用自定义状态目录时加`--workspace-data-dir`。`--gate`与`--preview`互斥；门禁不接受本次`--policy`或`--max-function-lines`覆盖。默认不带模式的scan继续保留原有关闭行为，避免旧自动化默默切换语义。

## 状态与退出码

| 门禁状态 | CLI退出码 | 条件 |
|---|---|---|
| `pass` | 0 | 可信必检清单非空，适用检查完整执行，规则已准入，当前证据仍有效，且无阻断项 |
| `block` | 1 | 有效策略下存在当前可信、已准入规则确认的阻断项；同时保留其他不完整信息 |
| `error` | 2 | 全局策略/输入/权限不可用，无法作可信判定 |
| `incomplete` | 3 | 无已确认阻断，但必检、准入、适用输入、工具或完整性条件未满足 |

当前生产清单只有`python.function_length@1`，固定80行，分类为`policy_debt`，准入状态为`report_only`，没有效果验收及准入证据。因此当前生产检查返回`incomplete/3`；零问题、空Python范围或全部排除都不能返回0。合成测试中的已准入规则只验证框架分支，不代表生产已开放阻断。

首版合成判定采用固定语义：每个已准入required规则、持当前有效凭据的观察均为阻断项，未另设严重度/数量过滤，也不应用旧`Policy.gate`配置。`confidence`仍是报告信号，不是额外授权来源。真实生产准入前必须把严重度集合、计数/重复口径、阈值与正式豁免条件形成可信版本并验证；不能只翻转`admission`标志就开放阻断。

对于未来真实已准入且适用的规则，完整执行后的零阻断项可以通过；“没有Finding”与“没有执行任何必检”不是同一件事。

## 可信来源与凭据

清单由工具宿主内置构造，保存策略版本、规则版本/实现、冻结配置、适用范围、预算及准入证据状态。`GET /api/gate-policy`只返回工具元数据，不读取项目。任务创建时固定清单SHA-256，worker在打开项目之前比对，并继续复核整体工具身份和权限版本。

仓库policy、模型返回、请求JSON和本次客户端参数不能删除必检项、改变阈值或把未准入规则改为阻断规则。哈希标识版本，不代替可信来源或效果验收。当前没有生产规则准入/注册接口。

未来CI还须固定已审的工具、规则和策略发行版本，并使用受管外部状态；不能先从被审PR安装并执行宿主分析器，再把它自报的内置清单视为可信。本轮没有部署CI，也不对已经能执行任意宿主代码的调用方提供OS隔离。

判定使用`VerificationContext`独立重算的原始Finding及当前进程内凭据。JSON的`verified/can_block`、复制对象、旧报告或伪造策略对象不能恢复资格。完整源码、依赖、规则、策略、预算和文件清单变化都有状态；权限撤销清除旧输出，不沿用先前阻断或通过。当前仍只声明获准Python范围，其他语言及全仓库不声称已经审查。

现有`local_user`基线批准是债务标注，不是正式门禁豁免。门禁固定`baseline_summary.mode=annotation_only`、`gate_exemptions_applied=0`；即使批准记录或JSON的哈希碰巧一致，也不能消除已准入阻断项。正式豁免的准入、审阅身份与生效流程须另行完成，不能由旧债务批准自动升级。

worker私有完成退出码与CI合同分开：worker可成功保存`incomplete/error`报告，网页任务显示报告已生成；门禁状态及报告中的`exit_code`才是判定。只有用户CLI的`scan --gate`按上表返回CI退出码。
