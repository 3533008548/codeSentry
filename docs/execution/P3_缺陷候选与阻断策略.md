## 首条缺陷候选

网页左侧“缺陷候选”提供显式检查，独立保存结果、历史和源码证据。首条规则为`python.assert_tuple@1`，检查`assert`条件是不是不含任何星号展开的非空元组字面量。

例如`assert (condition, "message")`的外层元组成功构造后真值为真，可能把本应写成`assert condition, "message"`的断言写错。成立条件是断言启用且元组构造完成；表达式本身仍可能产生副作用或异常，路径也可能不可达，不能据此断言项目实际发生了故障。[Python assert语义](https://docs.python.org/3.14/reference/simple_stmts.html#the-assert-statement)、[真值规则](https://docs.python.org/3.14/library/stdtypes.html#truth-value-testing)、[元组/圆括号表达式](https://docs.python.org/3.14/reference/expressions.html#parenthesized-forms)。

报告分类为`behavior_bug_candidate`，已确认行为缺陷数和阻断数均为0。`verified/confidence=1`仅表示语法谓词由确定性规则重算，不是“真实缺陷概率100%”。作者意图、可达性、副作用和运行后果仍未裁决。候选不进入旧P2 bug金标/precision/recall，不获得债务基线批准或门禁豁免。

空元组、正常的`assert condition, message`、字符串/注释中的文本不会命中。任何层级带`Starred`的条件都保守不评估，即便其他元素已经保证非空，也不扩大首版适用范围；未报告不表示无缺陷。方法、嵌套函数和相同断言的多次出现分别保留身份与位置。

访问权限、预算、解析失败、原始字节SHA-256和来源检查沿用现有机制；发布前复核输入清单和已读上下文，观察到变化时标不完整。权限撤销清除旧输出。源码跳转带本次候选任务身份，BOM/编码变化也会提示旧位置过期；这不是原子文件系统快照或OS隔离。

CLI入口与原预览、门禁互斥：

```powershell
codesentry scan /path/to/project --defects --confirm-access --json
```

已注册空间复用原范围，自定义工作台目录增加`--workspace-data-dir`。规则固定，不接受`--policy`、函数行数或客户端规则覆盖。完成仅报告返回3，不完整返回1，输入/权限错误返回2；JSON保留`gate_status=not_evaluated`。默认`--preview`仍只报告80行策略债务，不把两种结果混为一份。

## 冻结阻断策略

生产门禁策略版本升至2，加入可信、只读的`blocking_policy`：

| 字段 | 固定默认值 | 含义 |
|---|---|---|
| block_severities | critical、high | 仅在规则已准入且当前原始凭据有效时，才可能计入阻断 |
| max_new_findings | 0 | 计入的新问题超过允许数才阻断 |
| count_unit | unique_issue_occurrences | 按规则、路径、符号、结构锚点和出现序号计数 |

策略进入清单摘要，在打开项目之前校验。API、仓库配置和本次CLI不能扩大严重度豁免或允许数量。`can_block`仍是最低凭据资格，新增`eligible_for_blocking`表示同时命中严重度；`count_status`说明计数/不适用/歧义，`blocking`仅标记稳定身份排序后超出允许数的观察。所有观察保留。

重复/歧义身份不静默去重后宣称通过，也不占据或扩大允许额度；有其他唯一可信超额项时仍阻断并保留不完整信息。`confidence`不作为独立授权来源。旧债务批准仍只标注，正式门禁豁免数为0。

80行规则仍为LOW、report-only、未准入；新断言候选为MEDIUM、不可阻断且不进入生产必检清单。当前生产门禁仍不完整。本轮没有通过提高严重度或翻转准入标志制造生产阻断。
