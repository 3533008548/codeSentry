# P4：HTTP401与密钥来源冲突排查

日期：2026-10-30。

用户在确认发送片段后，模型审查记录显示 `HTTP 401`。本轮未读取目标代码，也未重放这次审查。

## 已核实的原因

- 服务当时使用的密钥来源是 `environment`；它与CodeSentry根目录`.env`中的值不一致，仅比较是否相等，没有输出值、长度或摘要。
- 使用两种来源分别访问DeepSeek官方 `GET /models`：环境变量密钥返回401，`.env`密钥返回200，且返回模型列表包含当前默认模型。
- 401属于密钥鉴权失败；余额不足使用402，不由本次401推断余额。见[官方错误码](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes/)、[官方模型列表接口](https://api-docs.deepseek.com/api/list-models/)。

因此，本次问题是另一把环境变量密钥按优先级覆盖了有效的文件密钥。读取成功仅证明配置存在，不等于供应商已经接受该密钥。

## 本次修复

新增根目录 [`start-workbench.cmd`](../../start-workbench.cmd)，固定使用本仓库`.env`和既有`.venv/workbench-data`。脚本通过`setlocal`仅在自己的进程及子进程中排除`DEEPSEEK_API_KEY`，不删除或修改系统环境变量，也不打印密钥。普通`codesentry serve`的环境变量优先规则保持原样。

确认工作台没有运行中的任务后，停止了已核对身份的旧服务，并通过该脚本隐藏启动新服务。重启后的配置接口确认：启动密钥来源为`env_file`，已启用项目的有效来源同样为`env_file`，服务可访问且没有自动创建分析任务。复用原数据目录，未调用文件权限或模型设置的写接口。

本轮只向DeepSeek发送两次模型列表鉴权请求，没有源码、项目数据或聊天消息，也没有模型生成请求。没有调用代码审查完成接口来冒充真实审查成功。只验证了实际启动脚本和运行状态，没有重跑无关算法或历史完整回归；P4质量指标不受这次鉴权修复替代。
