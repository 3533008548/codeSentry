## P7A 报告合并与跨文件汇总

`review-merge` 默认在本机合并。最多导入 32 份项目目录外的普通 JSON 文件，合计 32 MiB。批次报告的摘要须匹配工作空间本机数据库的签发记录。合并核对当前计划、权限版本、问题与模型配置。已完成行段填补旧缺口，重复观察去重，同一行段的不同完成结果标为冲突。当前范围有冲突或缺口时不生成汇总。旧批次报告缺少签发记录，需重新生成才能合并。

`--summary-requests` 明确授权汇总次数。请求发送已完成的模型观察，并限制结论引用已经核对位置的行段。观察超出单次输入预算时分组汇总，每组可保留若干结论与未知项。报告始终保留逐段观察。发布前复核源码、权限及模型配置，验证引用位置与判断结论质量分开。

## P7A 有界补跑

批次按已授权的行段 ID 独立校验。缺项、重复 ID 或错误引用只影响可定位的行段，无法归属到当前请求的条目会使该次回包失败。`review-run --retry-requests` 默认 0。启用后，每批最多补跑一次，只重新发送失败且可补跑的行段，整次请求数受计划和补跑预算约束。报告保留每次补跑的原因与实际尝试数。

汇总在 `--summary-requests` 中先为正常分组和最终汇总预留次数。剩余次数可用于引用或整数算式校验失败的分组或最终汇总，每个步骤最多补跑一次。同次执行中的成功分组直接沿用，补跑提示根据失败类型生成。补跑沿用相同的权限、源码快照、问题和模型。认证、限流、预算用尽、源码或权限变动会停止相应请求。

用真实 DeepSeek 和既有合成样例做故障注入。首次回包在本地注入错误引用后，第一批仅补发 `R1`，同批的 `R2` 至 `R4` 保留，随后正常完成第二批 `R5`。另一个回包在本地注入错误算式后，源码汇总用预留的一次请求通过校验，合计两次汇总请求。重试后的回答正确给出了总上下界，但仍把 trial 档最低值写成 `7`，源码实际为 `1`。本轮验证的是补跑与范围约束，保留该语义错误作为后续反例。[真实模型故障注入记录](../../evals/reports/p7a_bounded_retry_live_20261110.json)

最终覆盖与批次专项 33 项通过，包含已通过行段保留、预算耗尽、成功分组复用、补跑仍失败及补跑期间源码变动等反例。[批次与汇总测试](../../tests/test_batch_review.py)
